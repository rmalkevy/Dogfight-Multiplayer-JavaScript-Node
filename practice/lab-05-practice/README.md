# Lab 05: практика

Експерименти до [Lab 05](../../lab-05-realtime-networking.md) і його [нотаток](../../lab-05-realtime-networking.notes.md).
Кожен файл запускається окремо й показує одну ідею. Встановлювати нічого не треба
(Node 22+, без залежностей). У нотатках немає досліду з WebSocket, тому `ws` тут не потрібен; сокети є в [Lab 04](../lab-04-practice/).

## Порядок показу

| Файл | Запуск | Розділ нотаток | Що показує |
|---|---|---|---|
| `01-endianness.js` | `node 01-endianness.js` | §1 | `1.5` як Float32: LE `0 0 192 63`, BE `63 192 0 0`; `getUint16` без `true` читає big-endian |
| `02-typed-array-endian.js` | `node 02-typed-array-endian.js` | §2 | `Uint16Array` на байтах `[1, 0, 0, 1]` дає `[1, 256]` (порядок процесора); `DataView` з явним порядком |
| `03-json-vs-binary.js` | `node 03-json-vs-binary.js` | §3 | 8 кораблів: 345 проти 128 байтів; 20 сутностей на 30 Hz: ~26 проти ~9.6 KB/s; час 10 000 знімків |
| `04-timer-jitter.js` | `node 04-timer-jitter.js` | §4 | 100 тіків по 33 мс, гістограма інтервалів: `setInterval` і ланцюжок `setTimeout` дрейфують на ~100–150 мс, «старт + n × step» ні |
| `05-determinism.js` | `node 05-determinism.js` (двічі) | §5 | 1000 кроків `integrate`: однаковий хеш; `Math.random()` розводить хеші; seed дає той самий хеш |
| `browser.html` | відкрити в браузері | §5 | та сама симуляція (`sim.js`) у Chrome: хеші без випадковості і з seed 42 збігаються з Node |

## Примітки для показу

- Перед кожною частиною проси прогноз уголос, потім запускай. Частини розділені заголовками `--- A`, `--- B`.
- `02`: у нотатках очікування «щось на кшталт `256, 256`». Насправді на little-endian машині виходить `[1, 256]`:
  `[1, 0]` це 1, `[0, 1]` це 256. Варто сказати студентам, перш ніж вони звірять із нотатками.
- `01`, частина B: `getUint16(0)` без другого аргументу означає big-endian. У нотатках про це не сказано, добре питання студентам.
- `03`, частина C: мілісекунди залежать від машини, стабільне лише співвідношення (binary у кілька разів швидший).
  Розміри в байтах детерміновані.
- `04` іде ~10 с. Точні числа гістограми щоразу інші, форма та сама. У Node `setInterval` відраховує наступний тік
  від моменту, коли спрацював попередній, тому дрейфує майже як ланцюжок `setTimeout`. У частині C окремі інтервали
  дрижать навіть сильніше (є й коротші за 31 мс, бо тік наздоганяє ціль), але сотий тік приходить на ~3300 мс.
- `05`: у частині B хеші щоразу нові, а x відрізняється лише в шостому знаку, тобто «на око» розбіжності немає.
  Хеші A і C однакові між запусками й однакові з Chrome (перевірено: Node 26 і Chrome 156, обидва V8).
  Firefox і Safari не перевіряли; якщо хеш там інший, причина в `Math.exp`/`Math.cos`/`Math.hypot`, які стандарт не фіксує до біта.
- Для `browser.html` сервер не потрібен: `sim.js` підключено звичайним `<script>`, не модулем, тому `file://` працює.
